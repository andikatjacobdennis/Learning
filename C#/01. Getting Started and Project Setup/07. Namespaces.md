# Namespaces (C#)

Namespaces organize classes, interfaces, structs, enums, and prevent naming conflicts.

## Traditional Namespace

```csharp
namespace MyApp
{
    class Program
    {
        public void Run()
        {
        }
    }
}
```

---

## File-scoped Namespace (C# 10+)

```csharp
namespace MyApp;

class Program
{
    public void Run()
    {
    }
}
```

---

## Nested Namespaces

```csharp
namespace MyApp.Services
{
    class UserService
    {
    }
}
```

Equivalent:

```csharp
namespace MyApp
{
    namespace Services
    {
        class UserService
        {
        }
    }
}
```

---

## Using Namespace

```csharp
using MyApp.Services;

var service = new UserService();
```

---

## Namespace Alias

```csharp
using Services = MyApp.Services;

var service = new Services.UserService();
```

---

## Global Namespace

Classes without namespace belong to the global namespace.

```csharp
class Program
{
}
```

Access:

```csharp
global::Program
```

---

## Namespace in Project

Example structure:

```text
MyApp
│
├── Services
│   └── UserService.cs
│
├── Models
│   └── User.cs
│
└── Program.cs
```

`User.cs`

```csharp
namespace MyApp.Models;

public class User
{
    public string Name { get; set; }
}
```

`UserService.cs`

```csharp
namespace MyApp.Services;

using MyApp.Models;

public class UserService
{
    public User GetUser()
    {
        return new User();
    }
}
```

---

## Root Namespace

Defined in `.csproj`:

```xml
<PropertyGroup>
    <RootNamespace>MyCompany.MyApp</RootNamespace>
</PropertyGroup>
```

---

## Rules

* Namespace names should match project/folder structure.
* Use PascalCase naming.
* A file can contain multiple namespaces.
* File-scoped namespace can have only one namespace per file.

## Benefits

* Organizes large applications.
* Avoids class name conflicts.
* Improves code readability and maintainability.
